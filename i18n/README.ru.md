# Heiman Smart Home MCP — Руководство по использованию (Русский)

Запрашивайте данные и управляйте устройствами умного дома на естественном языке через ИИ-ассистента: освещение, кондиционеры, шторы, температура и влажность, журналы устройств, комнаты, сценарии и охрана.

| | |
| --- | --- |
| Конечная точка | `https://spmcp.heimanhome.com/mcp` |
| Транспорт | MCP Streamable HTTP |
| Авторизация | OAuth 2.1 с PKCE (вход через аккаунт умного дома) |
| Репозиторий | `https://github.com/heimanhome/heimanhome-mcp.git` |
| Поддержка | `help@heimanhome.com` |

> Английская версия [`../README.md`](../README.md) является авторитетной; этот перевод носит справочный характер.

## 1. Подключение и авторизация

1. Добавьте конечную точку в MCP-клиент, используя одну из конфигураций ниже.
2. Клиент откроет страницу авторизации — войдите через аккаунт умного дома.
3. Проверьте разрешения: по умолчанию выдаётся только чтение; права на запись включайте только для управления устройствами.
4. Подтвердите. Клиент сохранит токен; учётные данные не попадают в этот репозиторий.

## 2. Настройка клиента

**Универсальный `mcp.json`** (Claude Desktop, Cursor, Cline, Windsurf, Zed, VS Code + GitHub Copilot, MCP Inspector):

```json
{
  "mcpServers": {
    "heiman-smart-home": {
      "type": "streamableHttp",
      "url": "https://spmcp.heimanhome.com/mcp",
      "timeout": 30000
    }
  }
}
```

**Claude Code**:

```bash
claude mcp add --transport http heiman-smart-home https://spmcp.heimanhome.com/mcp
```

**Клиенты только с stdio** — мост через `mcp-remote`:

```json
{
  "mcpServers": {
    "heiman-smart-home": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://spmcp.heimanhome.com/mcp"]
    }
  }
}
```

**Облачные клиенты** (ChatGPT, Claude.ai, Copilot Studio, Gemini CLI, WorkBuddy / CodeBuddy): зарегистрируйте удалённый MCP-сервер в интерфейсе клиента, указав тот же URL.

## 3. Области доступа и безопасная запись

| Область | Позволяет |
| --- | --- |
| `device:read` | Списки устройств, состояние, возможности, прошивка, журналы, датчики |
| `device:control` | Включение/выключение, яркость, целевая температура, шторы |
| `scene:read` | Сценарии, комнаты, дома, автоматизации |
| `scene:execute` | Запуск, создание, изменение, удаление сценариев и автоматизаций |
| `security:control` | Постановка / снятие с охраны, подтверждение тревог |

- Без явного запроса выдаётся доступ только на чтение.
- Для ответственных действий требуется `confirm=true`; сначала используйте предпросмотр `dry_run=true`.
- При повторе команды передавайте `idempotent_key` и проверяйте `get_command_status(trace_id)`. Успешный ответ означает, что команда **принята**, а не обязательно выполнена устройством.
- `whoami` показывает личность и выданные области. При отказе исправьте область, параметр или подтверждение.

## 4. Примеры запросов

```
Установите яркость света в гостиной на 50 %
Какая сейчас температура и влажность в гостиной?
Включите кондиционер в гостиной и установите 26 °C
Закройте шторы и запустите сценарий «Дома»
Покажите среднюю температуру и влажность за последние 24 часа
```

Ассистент отвечает на вашем языке; примеры на 8 языках — в `connector-meta.json` → `i18n.locales`.

## 5. Частые проблемы

| Симптом | Решение |
| --- | --- |
| `401` / истекла авторизация | Переподключитесь и авторизуйтесь заново |
| Область не выдана | Повторите авторизацию и отметьте нужную область |
| Команда принята, устройство без изменений | Проверьте `get_command_status(trace_id)` и подождите |
| Слишком много запросов | Подождите, не повторяйте тот же вызов в цикле |
| Нет соединения | Проверьте поддержку Streamable HTTP + OAuth и доступность HTTPS |

## 6. Безопасность и приватность

- Команды управления меняют реальные устройства: проверяйте предпросмотр `dry_run` и минимизируйте права на запись.
- Токены и учётные данные остаются на сервере. Никогда не публикуйте токены и пароли в issue; сообщайте об уязвимостях на `help@heimanhome.com`.
- Оператор удалённого сервиса является контролёром данных — см. `OPEN-SOURCE-STATEMENT.md`.
